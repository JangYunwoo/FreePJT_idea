# Signal — 업로드형 데이터 자동분석 데모

CSV를 올리면 데이터 품질, 열별 분포, 수치 열 사이의 관계, 이상치 후보를 한 화면에서 확인하는 로컬 웹 데모입니다. [합성 주문 데이터](data/demo_orders.csv)로 바로 체험할 수 있습니다. 이 데이터는 실제 고객 정보를 포함하지 않습니다.

## 분석에 활용한 핵심 오픈소스

- **DuckDB**: 업로드 데이터의 행 수와 범주별 빈도 집계
- **PyOD**: Isolation Forest 모델로 여러 수치 열의 이상치 후보 탐지
- **fg-data-profiling**: 다운로드 가능한 전체 HTML 프로파일 생성

FastAPI는 CSV 업로드와 분석 API를 연결하는 **웹 구현 도구**로 사용했습니다. 데이터 분석이나 AI 알고리즘 자체의 핵심 오픈소스로 분류하지 않습니다.

단순한 LLM 문장 생성 데모가 아닙니다. AI 탐지는 학습된 트리 기반 모델의 점수로 수행합니다. 다만 비지도 이상치 후보는 실제 오류의 판정 결과가 아닙니다. 상관관계 역시 인과관계를 의미하지 않습니다.

AutoGluon을 이용한 예측 모델은 이번 업로드·탐색 데모에 포함하지 않았습니다. 목표 열을 정하고 평가·누수 방지 기준을 합의한 뒤 다음 단계로 추가하는 편이 안전합니다.

## Windows에서 실행

프로젝트 폴더에서 PowerShell을 열고 실행합니다. Python 3.11 또는 3.12가 필요합니다.

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe sample_data.py
.\venv\Scripts\python.exe -m uvicorn app:app --host 0.0.0.0 --port 8000
```

이 컴퓨터에서는 이미 `venv`와 샘플 CSV가 준비되어 있으므로 마지막 줄만 실행하면 됩니다. 브라우저에서 `http://127.0.0.1:8000`을 열어 **가상 데이터로 체험**을 누르세요. 직접 만든 CSV도 올릴 수 있습니다.

같은 와이파이의 다른 기기에서는 이 컴퓨터의 `ipconfig` 결과에 있는 Wi-Fi IPv4 주소를 확인하고 `http://<IPv4 주소>:8000`으로 접속합니다. Windows 방화벽에서 Python/포트 8000 접근을 허용해야 할 수 있고, 공유기의 게스트망 또는 기기 간 통신 차단 설정에서는 접속되지 않을 수 있습니다. 서버를 실행한 컴퓨터와 터미널은 켜둬야 합니다.

## 데모 범위와 주의사항

- UTF-8/CP949 CSV, 최대 8MB·20,000행·60열입니다.
- 업로드 파일은 서버 디스크에 저장하지 않습니다. 요청 처리 중 메모리에만 보관하며, 전체 프로파일은 HTML 파일로 사용자의 브라우저에 내려받습니다.
- 이상치 탐지는 30행 이상이고 유효한 수치 열이 2개 이상일 때만 실행합니다. 식별자 이름의 수치 열과 고유값이 너무 적은 열은 제외합니다.
- 전체 프로파일은 최대 5,000행을 재현 가능한 방식으로 표본 추출해 만듭니다.
- 인증과 암호화가 없는 **신뢰할 수 있는 로컬 네트워크용 데모**입니다. 민감한 실제 데이터를 올리거나 외부 인터넷에 그대로 공개하지 마세요.
- 샘플 데이터의 의도적 결측·중복·극단값은 [정답 메모](data/demo_truth.json)에 기록했습니다. 비지도 모델의 탐지 결과와 이 메모가 반드시 일치하지는 않습니다.

## 설명

이 데모는 **오픈소스 자체를 개발·수정한 프로젝트가 아니라, 기존 오픈소스를 조합해 새 서비스를 만든 사례**입니다. 각 프로젝트가 원래 해결하려는 문제와 여기서 맡은 역할은 다음과 같습니다.

| 오픈소스 · 원본 링크 | 원래 만들어진 목적 | 이 데모에서 사용한 부분 |
| --- | --- | --- |
| [DuckDB](https://github.com/duckdb/duckdb) | 애플리케이션 안에서 SQL로 데이터를 빠르게 분석하는 데이터베이스 | 업로드한 표를 등록해 행 수와 범주형 열의 값별 빈도를 집계 |
| [PyOD](https://github.com/yzhao062/pyod) | 다양한 알고리즘으로 이상치·특이 패턴을 탐지하는 Python 라이브러리 | `IForest`를 수치 열에 학습시켜 확인할 행의 점수를 계산 |
| [fg-data-profiling](https://github.com/Data-Centric-AI-Community/fg-data-profiling) | 표 데이터의 탐색적 분석과 품질 정보를 자동으로 요약·보고하는 도구 | 전체 프로파일을 HTML로 생성해 다운로드 제공 |

작업 순서는 다음과 같습니다.

1. 업로드된 CSV를 읽고 열·결측·중복 등을 확인합니다. 서로 다른 열 이름의 CSV도 처리하도록 특정 주문 데이터의 열 이름에 의존하지 않았습니다.
2. DuckDB로 기본 집계를 하고, 수치 열을 골라 PyOD의 Isolation Forest로 이상치 후보를 찾습니다. 실제 데이터에서 모델을 다시 학습하며, 사전 학습된 범용 가중치나 LLM 응답을 불러오는 방식이 아닙니다.
3. 결과를 근거 카드·분포 그래프·원본/이상치 행 표로 구성하고, 필요하면 fg-data-profiling 보고서를 별도로 생성합니다. 이 처리 흐름과 화면, 합성 예시 데이터는 이 프로젝트에서 구현했습니다.

## 오픈소스 선정 이유

서로 다른 열 구성의 CSV를 다루면서, 기본 집계·모델 기반 이상치 탐지·상세 보고서를 각각 검증된 도구에 맡기기 위해 세 프로젝트를 선택했습니다.

- **DuckDB — 표 데이터 집계:** 업로드한 데이터를 메모리의 SQL 테이블처럼 등록하고, 범주 열마다 값별 빈도를 계산할 수 있어 선택했습니다. 현재 데모에서는 행 수와 범주별 집계에만 사용합니다. 이 정도 크기의 CSV는 pandas만으로도 처리할 수 있으므로, DuckDB를 썼다는 사실 자체를 성능 우위로 주장하지는 않습니다.
- **PyOD — 이상치 탐지 모델:** 여러 탐지 알고리즘을 공통된 방식으로 학습·평가할 수 있어 선택했습니다. 현재는 수치 열을 전처리한 뒤 `IForest`를 학습하고 행별 이상치 점수를 받습니다. 열 구성이 다른 CSV에도 같은 흐름을 적용할 수 있고, 이후 다른 탐지기를 비교할 출발점이 됩니다. 다만 지금은 알고리즘 비교나 탐지 정확도 검증까지 한 상태는 아닙니다.
- **fg-data-profiling — 상세 데이터 점검:** 열별 통계와 데이터 품질 정보를 HTML 보고서로 생성할 수 있어 선택했습니다. 화면에는 먼저 볼 항목을 간단히 보여주고, 상세한 탐색이 필요할 때 이 도구의 보고서를 내려받게 했습니다. 보고서 생성 기능을 직접 다시 구현하지 않아도 된다는 점이 현재 데모에 적합했습니다.

FastAPI는 이 세 분석 기능을 업로드 화면과 연결하기 위한 웹 프레임워크입니다. 분석용 오픈소스를 선정한 이유와는 별개이며, 위 프로젝트들의 원본 코드를 수정하거나 기여한 것은 아닙니다.

## AI 고도화 방향

현재 AI 기능은 수치 열을 골라 PyOD의 Isolation Forest 한 가지 모델로 이상치 후보를 찾는 단계입니다. 분석 가능한 데이터에서는 약 5%를 이상치로 표시하지만, 이것만으로 실제 오류 여부나 이상하다고 판단한 이유를 알 수는 없습니다. 다음 단계의 목표는 **서로 다른 CSV에서 확인할 만한 행을 찾고, 그 근거와 성능을 검증 가능한 형태로 보여주는 분석 엔진**입니다.

1. **데이터에 맞는 특징 생성:** 열을 식별자·날짜·범주형·수치형 등으로 구분합니다. `purchase_key` 같은 식별자는 모델 입력에서 제외하고, 날짜가 있으면 시간에 따른 급변을, 상품·지역 같은 분류가 있으면 같은 집단 안에서 벗어난 값을 살펴봅니다. 모든 CSV의 열 의미를 자동으로 정확히 이해한다고 가정하지 않고, 인식 결과를 사용자가 확인·수정할 수 있게 합니다.
2. **여러 탐지 모델의 비교:** 현재의 Isolation Forest와 [PyOD의 ECOD·LOF 등](https://pyod.readthedocs.io/en/latest/examples/tabular.html)을 같은 데이터에서 비교합니다. 모델마다 이상치 점수의 척도가 다르므로 [점수를 표준화한 뒤 결합](https://pyod.readthedocs.io/en/latest/examples/combination.html)하고, 모델 간 판단이 일치하는지 보여줍니다. 고정된 5% 판정만 제공하기보다 사용자가 검토할 상위 건수와 임계값을 조절할 수 있게 합니다.
3. **행별 탐지 근거:** 단순 점수 대신 해당 행의 어떤 값이 비슷한 행들과 크게 다른지 보여줍니다. 예를 들어 같은 상품군의 일반적인 배송 거리·처리 시간과 해당 주문을 비교하고, 각 모델의 점수와 판단도 함께 표시합니다. 이는 이상하게 보이는 **특징에 대한 설명**이지 문제의 원인을 확정하는 설명은 아닙니다.
4. **성능 평가와 피드백:** 의도적으로 이상을 심은 합성 데이터뿐 아니라 정답이 있는 공개 데이터에서도 상위 `k`건 중 실제 이상이 몇 건인지(Precision@k), 오탐이 얼마나 발생하는지 평가합니다. 여러 열 구성의 CSV에서 결과를 비교하고, 사용자가 이상치 후보를 맞음/아님으로 검토한 기록을 임계값 조정이나 후속 모델 학습에 활용합니다.

데이터 양과 기간이 충분하다면 [오토인코더 기반 탐지](https://pyod.readthedocs.io/en/latest/)도 비교 대상으로 추가할 수 있습니다. 다만 현재의 소규모 데모 CSV에 딥러닝을 적용하는 것 자체를 성능 향상으로 간주하지는 않습니다. 6~7주 프로젝트에서는 모델 종류를 늘리는 것보다 **특징 생성 → 모델 비교 → 행별 설명 → 정답 데이터로 검증**하는 흐름을 완성하는 데 우선순위를 둡니다. 이 방향이라면 AI 담당자는 데이터·모델·평가를, 프론트엔드는 근거 탐색과 사용자 검토 화면을, 백엔드·인프라는 분석 작업과 결과 저장·배포를 각각 맡을 수 있습니다.

## 6명 팀 구성과 6~7주 범위

팀의 공동 목표는 **열 구성이 다른 CSV에서도 검토할 만한 이상치 후보를 찾고, 사용자가 그 근거를 확인하며, 탐지 성능을 검증할 수 있는 서비스**를 만드는 것입니다. 아래는 역할을 나누기 위한 초안이며, 구현 과정에서 작업량에 맞춰 조정할 수 있습니다.

| 역할 | 주요 담당 결과물 |
| --- | --- |
| AI 1명 | 열 유형 인식, 전처리와 특징 생성, 데이터에 따른 분석 가능 여부 판단 |
| AI 1명 | 2~3개 이상치 모델 비교, 행별 탐지 근거, 정답 데이터 기반 성능 평가 |
| 백엔드 1명 | CSV 업로드·분석 API, 분석 결과 저장·조회, 사용자 검토 결과 기록 |
| 인프라 겸 백엔드 1명 | 실행 환경과 배포, CI/CD·로그, 오래 걸리는 분석 작업 처리와 백엔드 지원 |
| 프론트엔드 1명 | 업로드 흐름, 열 유형 확인·수정, 분석 옵션 설정 화면 |
| 프론트엔드 1명 | 이상치 목록과 행별 근거 탐색, 비교 시각화, 정상/이상 판정 화면 |

프론트엔드는 결과 차트만 그리는 역할이 아닙니다. 사용자가 식별자 열을 분석에서 제외하거나, 검토할 상위 건수를 정하거나, 모델이 제시한 후보를 정상/이상으로 판정할 수 있도록 **분석 과정에 개입하는 경험**을 만드는 것이 핵심입니다.

6~7주 안에 우선 완성할 범위는 **열 유형 인식과 사용자 수정, 2~3개 모델 비교, 행별 근거, 정답이 있는 데이터로 평가, 검토 화면**입니다. 오토인코더, 사용자 피드백을 이용한 재학습, 복잡한 분산 인프라는 기본 기능과 평가가 완료된 뒤 검토할 확장 항목입니다. 분석 작업이 실제로 오래 걸릴 때에만 별도 작업 큐를 도입하며, 처음부터 인프라 규모를 키우는 것을 목표로 삼지 않습니다.

가장 중요한 선행 작업은 **평가 기준 마련**입니다. 의도적으로 이상을 넣은 합성 데이터와 정답이 있는 공개 데이터를 준비하고, 상위 후보의 적중률과 오탐을 측정해야 합니다. 그래야 모델이나 화면을 추가했을 때 실제로 분석 경험이 좋아졌는지 팀 전체가 같은 기준으로 판단할 수 있습니다.
